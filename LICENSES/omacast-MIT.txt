omacast describes its own ranker as a clean-room port of Raycast's root-search
algorithm and contains no Raycast code. Spotlight inherits that provenance.

Local changes, so a future diff against upstream is legible:

  * candidates are built from Spotlight rows by toCandidate();
  * the optional flea-search branch (fleaRecord/fleaMatch/FLEA_*) is omitted —
    the catalog here is a few hundred rows, so the in-process matcher is enough;
  * contact/menu-bar/quicklink type priorities are kept but never produced;
  * chords are searched only for chord-like queries (see buildRecord), instead
    of every chord being a keyword on every query;
  * keyword-match scores are compared, where upstream discards them;
  * a title that starts with the query outranks a whole-word hit later in the
    title, fixing "calc" ranking "LibreOffice Calc" above "Calculator";
  * one- to three-letter queries match titles only and use a fixed score floor
    (shortFloor), because a flat gap penalty makes long keyword strings match
    almost anything at that length;
  * the four- and five-letter threshold is stricter than upstream's curve, so
    scattered title matches do not clear it;
  * ties prefer the shorter title;
  * natural collation is written out rather than delegated to
    localeCompare({numeric: true}), which Qt is not guaranteed to honour.
